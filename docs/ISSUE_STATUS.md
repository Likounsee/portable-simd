# Portable SIMD issue status

> Audit date: 2026-11-28  
> Code audited: `Likounsee/portable-simd` on `main`.  
> Issue source: open issues in `rust-lang/portable-simd` (91 issues returned by the GitHub issues API, excluding pull requests).  
>
> This is a **fork implementation audit**, not a claim that upstream issues have been closed. An upstream issue can remain open while the corresponding implementation already exists here. “Done” means the relevant API/implementation is present in this fork; it does not imply upstream acceptance or a passing CI run for every target.

## Status key

- **DONE — in fork**: implementation and/or regression coverage already exists; do not reimplement blindly.
- **PARTIAL — in fork**: some of the requested behavior exists, but coverage, portability, performance, or scope remains.
- **API proposal**: requires a new public API, a public naming/design decision, or stabilization policy. Keep it out of implementation work until the API owners decide.
- **EXTERNAL**: primarily blocked on rustc, LLVM, a backend, or an upstream compiler intrinsic.
- **INVESTIGATE**: needs a current reproducer, target-specific measurement, or deeper source audit before calling it fixed.

## Executive summary

The fork already contains substantial work beyond the old upstream issue checklists: integer overflowing/saturating/wrapping operations, rotations, `to_mask`, `mul_high`, generic aliases, `gather_unchecked`, signed i32 gather, transpose, concat/split, dynamic byte swizzling, compress/expand, masked memory operations, pairwise reductions, float bit operations, and algebraic float operations.

The clearest already-addressed issue threads are **#537, #505, #481, #475, #479, #447, #440, #329, #306, #277, #240, #235, #211 and #202**. Several other threads are only partly covered or are fundamentally compiler/codegen issues.
